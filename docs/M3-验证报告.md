## 2. 六方言驱动

| 方言 | 实现 | 验证 |
|---|---|---|
| SQLite | `rusqlite`（原有） | `core/tests/sqlite_flow.rs` 11 个用例 |
| PostgreSQL | `tokio-postgres`（原有） | `db-postgres/tests/live.rs`（需 `RUSTDB_LIVE_TESTS=1` + Docker） |
| MySQL / MariaDB | `mysql_async`（原有） | `db-mysql/tests/live.rs`（同上） |
| **SQL Server** | `tiberius` 0.13（TDS + rustls）：连接/查询/流式取行/事务/元数据 `sys.*`/分页 `OFFSET…FETCH`/协作式取消 | `db-mssql` 7 个单测 + **真库 live 用例通过**（见 2.1） |
| **Oracle** | `oracle` 0.6（ODPI-C，**thin 模式**）：连接串解析/`SELECT 1 FROM dual`/DML/事务/`ALTER SESSION SET CURRENT_SCHEMA`/`all_*` 元数据/`DBMS_METADATA.GET_DDL` | `db-oracle` 7 个单测（连通未验证，见 2.2） |

### 2.1 SQL Server 真库验证（已通过）

环境：Docker 容器 `rustdb-mssql`（`mcr.microsoft.com/mssql/server:2022-latest`，端口 51433），
种子数据 `shop.channels`（2 行）/ `shop.orders`（3 行），一键脚本 `scripts/setup-live.sh mssql`。

```bash
RUSTDB_LIVE_TESTS=1 cargo test -p rustdb-db-mssql --test live     # 1 passed
```

覆盖：聚合查询（中文列值 + GROUP BY + ORDER BY）、元数据（schema 列表 / 表列表 / 列类型 / **主键标记** / 索引）、
事务（插入 → `ROLLBACK` → 复查为 0 行）。

> 顺带修掉一个真 bug：`sys.columns` 查询没有主键位，列的 `is_primary_key` 一直是 false；
> 现由 `sys.indexes.is_primary_key` 反推标记（`db-mssql/src/lib.rs::table()`）。

### 2.2 Oracle：thin 模式修正 + 尚未连通验证

- **修正**：驱动原先生成 `//host:port/service`（thick / EZConnect 写法），而本 crate 编译时**没有**启用
  `thick` 特性 ⇒ 永远连不上。现改为 `host:port/service`（thin 兼容）；thin 模式**不需要**安装 Instant Client。
  驱动头部说明与 `DPI-1047` 的 hint 同步更新。
- **未验证**：拉 `gvenzl/oracle-free:23-slim` 时**系统盘被写满**（Docker 虚拟磁盘涨到 11.7GB，C 盘归零），
  镜像拉取失败，Oracle 实例没能起来。live 用例已写好（`db-oracle/tests/live.rs`），
  有环境时执行 `scripts/setup-live.sh oracle` +
  `RUSTDB_LIVE_TESTS=1 cargo test -p rustdb-db-oracle --test live` 即可。

**显式降级（R5）**：

1. Oracle 取消：`oracle::Connection` 是 `Send` 非 `Sync`，无法在查询阻塞时从旁路线程调用 `break_execution()`，
   `Capabilities.cancel = None`，代码注释与文档 6.3 均已写明。
2. SQL Server 的「切 schema」只记录不执行（T-SQL 无 `SET SCHEMA`，改默认 schema 要 `ALTER USER`）。

## 3. 数据编辑（F-35~F-38）

模块：`core/src/edit.rs`（纯逻辑，无 IO）。

| 能力 | 实现 | 测试 |
|---|---|---|
| 双击单元格进入编辑 | `MainView::begin_cell_edit` → 编辑条（输入 + 设为 NULL + 确定/取消） | `double_click_opens_edit_bar` |
| 类型感知校验 | `parse_cell_text`：int/float/decimal/bool/date/time/timestamp/timestamptz/uuid/json/text | `parse_cell_text_is_type_aware` |
| NULL 与空串区分 | 「设为 NULL」直接落 `Value::Null`；空串存 `Text("")` | `null_edit_is_distinct_from_empty_string` |
| 只改脏列 | `UPDATE … SET` 只含实际改动列 | `cell_edit_builds_update_statement` |
| 主键定位 | `WHERE` 用主键原值；NULL 用 `IS NULL` | `edit::tests::null_uses_is_null_in_where` |
| 无主键限制 | Update/Delete 直接拒绝（可 Insert） | `table_without_pk_can_only_insert`、`delete_requires_primary_key` |
| 单事务批量提交 | `SessionCmd::EditBatch`：无事务时 `BEGIN → 全部 → COMMIT`，失败 `ROLLBACK` | `change_set_commits_and_rolls_back_on_conflict` |
| 乐观并发 | 逐语句比对影响行数，`UPDATE/DELETE` 影响 0 行 → 判冲突并整体回滚 | 同上（第二段：过期主键触发 `未命中任何行` 并验证行仍在） |
| 已有手工事务 | 加入用户事务，不自动提交 | 代码路径 `owned_tx = tx.is_none()` |
| SQL 预览 | 底栏「预览」浮层，可复制 | `preview_changes` + `edit-preview-panel` |

## 4. 表设计器 + 迁移计划（F-39 / F-40）

模块：`core/src/migration.rs`（`plan_changes` / `plan_create_table`）。

| 场景 | 行为 | 测试 |
|---|---|---|
| 加列 | `ALTER TABLE … ADD COLUMN`，按方言引用符 | `add_column_is_safe_and_quoted_per_dialect` |
| 删列 | 标 `destructive` + 「数据不可恢复」提示 | `drop_column_is_destructive_with_rollback_note` |
| 改类型/非空 | PG `ALTER COLUMN … TYPE` / MySQL `MODIFY COLUMN` / MSSQL `ALTER COLUMN` | `type_change_follows_dialect_syntax` |
| SQLite 改列 | **不猜**：返回 `unsupported`「需要重建表」 | `sqlite_reports_unsupported_instead_of_guessing` |
| 非空新列无默认值 | 拒绝并说明原因 | `new_not_null_column_requires_default` |
| 删主键列 | 拒绝 | `primary_key_cannot_be_dropped` |
| 建表 | `CREATE TABLE` 按草稿顺序 | `create_table_plan_lists_columns_in_order` |
| DDL 事务性 | MySQL/MariaDB 标 `transactional = false` | `mysql_alter_is_not_transactional` |
| UI | 面板可删列、加列、预览 DDL、执行（走单事务通道） | `table_designer_edits_drafts` |

> 索引/外键/约束/表选项页签留待后续版本（文档 10.11 已声明范围）。

## 5. 本轮修掉的坑

| 现象 | 根因 | 修法 |
|---|---|---|
| 点表面板里的按钮会把面板关掉 | 全屏遮罩的 `on_click` 抢走了点击 | 设计器改为非模态面板，去掉遮罩，用 ✕ 关闭 |
| 面板内容被压成 70px 高 | 只有 `max_h` 时 `flex_1` 子项塌陷 | 给面板固定高度 |
| 变更集「改回原值」仍留在待提交列表 | 未做逐列回退判定 | `record_cell` 检查全部脏列是否等于原值，全等则整行撤销 |
| PG 限定名多了一段 catalog | 误以为 PG 不带库名 | 以 `object_from_clause` 实际输出为准修正测试期望 |
