## 4. 打包（`scripts/package.ps1`）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\package.ps1
```

| 环节 | 结果 |
|---|---|
| `cargo build --release -p rustdb --bin rustdb` | 脚本内执行 |
| 暂存目录 | `dist/RustDb-<version>-windows-x64/`（exe + README + 需求文档 + M3/M4/M5 报告） |
| 压缩 | `Compress-Archive` → `RustDb-<version>-windows-x64.zip` |
| 验证 | 以 `-Profile debug -SkipBuild -SkipZip` 跑通，产出 `rustdb.exe = 65 MB`（debug） |

> 脚本为 **ASCII-only**：PowerShell 5.1 会把无 BOM 的 UTF-8 `.ps1` 按 ANSI 解码，中文注释会导致行尾换行丢失、参数失效。

## 5. 真库环境一键脚本（本轮新增）

`scripts/setup-live.sh`（Git Bash / WSL 可直接跑）：

```bash
scripts/setup-live.sh mssql     # 起 SQL Server 容器（51433）+ 建库建表播种
scripts/setup-live.sh oracle    # 起 Oracle 容器（51521）+ 播种
scripts/setup-live.sh all

RUSTDB_LIVE_TESTS=1 cargo test -p rustdb-db-mssql --test live
RUSTDB_LIVE_TESTS=1 cargo test -p rustdb-db-oracle --test live
```

口令走 `.tmp/mssql.env` / 脚本内变量，**不写进仓库的连接配置**；生产连接仍走 keyring。

## 6. 磁盘事故与处置（重要）

本轮拉 Oracle 镜像时把**系统盘写满**了：

| 现象 | 原因 |
|---|---|
| C 盘可用空间 8.2GB → 0 | Docker 虚拟磁盘 `docker_data.vhdx` 涨到 **11.68GB**（Oracle 镜像层），VHDX 不会自动收缩 |
| `cargo build` 报 `磁盘空间不足` / `LNK1104` | 宿主盘满，链接器写不出 `.exe` |
| `docker ps` 无输出 | Docker 守护进程在磁盘写满时挂掉 |

处置与遗留：

1. 已删 `target/debug/incremental` 临时释放 7.1GB，随后**磁盘再次被 Docker 写满**；
2. 用户拒绝了删除 `target/debug/deps` 的请求，因此本轮**没有**再删构建产物；
3. 需要用户侧配合（任选其一）：
   - 清理 Docker 里停用的镜像/容器（`dolphinscheduler-*`、`postgres:15.2` 等约 4GB）后执行
     `wsl --shutdown` + 压缩 VHDX，或直接 `docker system prune`；
   - 或把 `CARGO_TARGET_DIR` 指到别的盘。
4. **磁盘腾出后**必须重跑：`cargo test --workspace`（本轮新增的流式 / 会话 / 红队 / mssql live 用例
   已分别单独跑通，但全量回归是在磁盘事故前那版代码上跑的）。

> 教训：拉数据库镜像前先 `df -h` 看余量（Oracle slim 解包后约 2.5GB，SQL Server 约 1.5GB），
> Docker 的 VHDX 不会自动缩容。
