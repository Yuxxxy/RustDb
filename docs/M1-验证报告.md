# M1 验证报告 · PostgreSQL / MySQL 真实驱动与切库

日期：2026-10-19
环境：Windows 11 · Docker 28.3.0 · `postgres:13` · `mysql:8.0`

## 1. 容器

| 容器 | 镜像 | 端口映射 | 账号 / 库 |
|---|---|---|---|
| `rustdb-pg` | `postgres:13` | `55432 -> 5432` | `postgres / rustdb` · `rustdb_test` |
| `rustdb-mysql` | `mysql:8.0` | `53306 -> 3306` | `root / rustdb` · `rustdb_test` |

启动命令：

```bash
docker run -d --name rustdb-pg \
  -e POSTGRES_PASSWORD=rustdb -e POSTGRES_DB=rustdb_test \
  -p 55432:5432 postgres:13

docker run -d --name rustdb-mysql \
  -e MYSQL_ROOT_PASSWORD=rustdb -e MYSQL_DATABASE=rustdb_test \
  -p 53306:3306 mysql:8.0
```

## 2. 测试数据

PostgreSQL：`shop.channels` / `shop.orders`，3 渠道、4 订单。
MySQL：`rustdb_test.channels` / `rustdb_test.orders`，同样数据。

> 注意：MySQL 灌数据必须带 `--default-character-set=utf8mb4`，否则中文会被客户端按 latin1 二次编码（本轮实际踩到，驱动本身读取是正确的）。

## 3. 测试结果

```bash
# 驱动契约（真实库）
RUSTDB_LIVE_TESTS=1 cargo test -p rustdb-db-postgres -p rustdb-db-mysql --test live

# 核心层切库链路（真实 PG）
RUSTDB_LIVE_TESTS=1 cargo test -p rustdb-core --test sqlite_flow

# 全量（无 Docker 时 live 用例自动跳过）
cargo test --workspace
```

| 用例 | 覆盖 | 结果 |
|---|---|---|
| `pg_live_query_metadata_and_switch_schema` | 连接 → 聚合查询 → namespaces → objects → `SET search_path` → 非限定表名查询 | ✅ |
| `mysql_live_query_metadata_and_switch_database` | 连接 → 聚合查询（utf8mb4）→ schemata → objects → `USE` → 非限定表名查询 | ✅ |
| `pg_namespace_switch_through_core` | `Core::switch_namespace` → Actor → `NamespaceChanged` → 重新加载对象 → 查询 | ✅ |
| `cargo test --workspace` | SQLite 端到端 + 布局 + SQL 语言服务 | ✅ 3+1+3+… 全绿 |

## 5. 当前限制

| 项 | 现状 | 计划 |
|---|---|---|
| PG / MySQL 类型信息 | 走 text protocol，列类型标记为 `text` | M2 改 prepare/query，拿真实类型 |
| MySQL 事务 | 连接池模式下无法绑定同一连接，返回 `Unsupported` | M2 会话级连接 |
| MySQL 切库 | 每条池连接执行 `USE`（不是池级状态） | M2 会话级连接后自然收敛 |
| TLS | PG `require/verify-*` 明确报不支持；MySQL 未启用 TLS | M2 |
| 流式结果 | 两个驱动均先收集再交回（`streaming_rows = false`） | M2 通道流式 |
| 跨库切换 | PG 仅支持同库切 schema；跨库需新建连接（明确提示） | 保持 |
