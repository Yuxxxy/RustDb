## 1. 能力位（`db-api::Capabilities`）

新增 7 个能力位，全部带 `#[serde(default)]`：旧配置文件 / 旧事件 JSON 反序列化时按 `false` 处理，
**UI 隐藏入口而不是假装支持**（延续 R5「不静默降级」）。

| 能力位 | 语义 | 六方言当前取值 | 未开启原因 |
|---|---|---|---|
| `dml_preview` | DML 可改写为只读预览（F-63） | **全部 true** | 改写器在 core，方言只需声明 |
| `routine_source_edit` | 例程源码可读可存（F-82） | **全部 true** | 源码读写链路已落地（9.24） |

## 2. `sql-lang` 增补（全部纯函数）

| 文件 | 对应需求 | 能力 |
|---|---|---|
| `lex.rs` | 公共底座 | 无损词法：`'…'`（`''`/反斜杠）、`"…"` / `` `…` ``、`$tag$…$tag$`、嵌套 `/* */`、`#` 行注释（但 `#{x}` 不当注释）、数字/词/标点 |
| `params.rs` | **F-62** | `?` / `:name` / `${name}` / `#{name}` / `@name` 识别；`::` 类型转换不误判；`@@version` 不当参数；方言冲突禁用（T-SQL/MySQL 关 `@name`）；`ParamValue::{Text,Number,Bool,Null,Raw,List}` 渲染；原始 SQL 参数双处告警；`@set name = value` 提取（保留行号） |
| `script.rs` | **F-64** | 脚本切分：`GO`（含 `GO 5` / `GO --注释`）、MySQL `DELIMITER`、dollar quote、CRLF；**纯注释片段不产出语句**；带 1-based 行号与字节区间 |
| `position.rs` | **F-61** | `LineIndex`：字节偏移 ↔ 1-based 行列，覆盖 CRLF（`\r` 不计列）、Tab、多字节（汉字 3 字节 = 1 列）、越界夹取 |
| `flavor.rs` | 公共 | 词法/脚本周边的方言归类（不依赖 `db-api`，保持 sql-lang 零依赖） |

**测试**：`cargo test -p rustdb-sql-lang` → **33 passed**（原 3 个 + 新增 30 个）。

关键用例：

- `dollar_quote_is_one_string_token`：函数体里的 `;` 不切分；
- `mysql_delimiter_keeps_procedure_body_whole`：存储过程整体成一条；
- `tsql_go_separates_batches`：`GO 5 -- 重复执行` 也识别；
- `comment_only_chunks_are_dropped`：`-- 说明` 单独一行不会变空语句；
- `colon_cast_is_not_a_parameter`：`'1'::int` 不产生参数；
- `multibyte_chars_count_as_one_column` + `crlf_does_not_count_as_a_column`：错误定位换算。

## 3. `core` 增补

### 3.1 DML 预览（F-63，`core/src/preview.rs`）

| 语句 | 改写 | 降级条件 |
|---|---|---|
| `UPDATE t SET a=e1, b=e2 [WHERE …]` | `SELECT *, e1 AS "a(new)", e2 AS "b(new)" FROM t [WHERE …]` | `UPDATE … FROM/JOIN`、多语句、SET 无法解析 |
| `DELETE FROM t [WHERE …]` | `SELECT * FROM t [WHERE …]` | `USING` / `JOIN` |
| `INSERT INTO t (a,b) VALUES (…),(…)` | `SELECT v1 AS a, v2 AS b UNION ALL SELECT …` | `INSERT … SELECT`、`DEFAULT`、列数不一致、含 `ON CONFLICT` 时给提示 |

- **零写入**：构建器只产出 `SELECT`，并在 `build()` 里 `debug_assert!(is_read_only(sql))`；集成测试用真库断言预览后数据未变。
- **同一构建器**：预览 SQL 与编辑器语句同源（同一段文本 + 同一套标识符引用），不存在两套拼接。
- **非确定性提示**：`NOW(` / `CURRENT_TIMESTAMP` / `RANDOM(` / `UUID(` / `NEXTVAL(` / `NEXT VALUE FOR` / `SYSDATE` / `NEWID(` 等命中即在 `notes` 标注「预览值可能不同」。
- **无 WHERE** 给提示但**不阻断**。
- 标识符引用按方言：`"a(new)"` / `` `a(new)` `` / `[a(new)]`。

### 3.2 运行记录（F-65，`core/src/runs.rs` + `ResultStore`）

- `RunLog`：每次执行一条 `RunRecord`（SQL 摘要 / 类型 / 起止 / 状态 / 结果集列表 / 行数 / 影响行数 / 固定位）。
- `tab_label()` 直接给 UI 用：`#2 · 1 行受影响 · 8 ms`。
- **固定项不参与淘汰**；`trim()` 只淘汰最旧的未固定记录，并把被淘汰记录返回给调用方释放结果集。
- `ResultStore` 新增：`set_pinned` / `is_pinned` / `remove` / `remove_if_unreferenced` / `evict_unpinned`（跳过固定、跳过 `Streaming`、跳过当前运行）。
- 接线：`session_actor::execute_batch` 登记 → 每条语句 `attach_result` → 收尾按条数上限 + 内存预算淘汰（含「保护本次运行结果」）。

### 3.3 历史增强（F-68，`core/src/history.rs`）

- 来源枚举 `HistorySource::{Manual,Ai,Mcp,Cli,File}` + `label()`；
- `finish_with(..., affected)` 记录影响行数；
- `HistoryFilter`：数据源、关键字、`from_ms`/`to_ms`（含边界）、来源、仅固定、条数上限；
- 保留条数可配：`HISTORY_LIMIT_CHOICES = [200, 1000, 5000, 10000, 0]`（**0 = 不限**），`set_limit()` 调小立即清理；
- 持久化（F-68）：`HistoryStore::with_path(limit, path)` 载入 JSONL（损坏行跳过、未完成执行丢弃），
  执行结束 / 固定 / 删除 / 清空 / 改上限时写全量快照（临时文件 + 替换），失败只记日志；
- 旧 API `list(profile, needle)` / `begin` / `finish` 保持兼容。

### 3.4 Core 门面

| 方法 | 说明 |
|---|---|
| `Core::runs()` | 运行记录仓库（UI / 后续 MCP 共用） |
| `Core::preview_dml(session, sql)` | 能力位 `dml_preview` 关闭或改写不安全时返回 `Unsupported{reason}`，**不阻断**执行 |

| 方言策略 | `core/src/routine.rs` | `routine_support(db_kind, routine)` 给出「保存方式 + 源码形态 + 不能保存的原因」。**UI 零 `match DbKind`**：面板只读返回值 |
| 保存方式 | `SaveStrategy::{CreateOrReplace, CreateOrAlter, DropAndCreate, Unsupported}` | PG 视图 / 函数 / 过程与 Oracle 全部例程 → `CREATE OR REPLACE`；MSSQL 视图 / 过程 → `CREATE OR ALTER`；MySQL 过程 / 函数 / 触发器与 SQLite 视图 / 触发器 → 先 `DROP` 再 `CREATE`（**带显式警告**）；MSSQL 函数 / 触发器与物化视图 → `Unsupported` 并给出原因 |
| 源码形态 | `SourceShape::{FullStatement, BodyOnly}` | 完整 `CREATE` 语句只改关键字；SQL Server 的 `OBJECT_DEFINITION` 只给例程体，需按方言补出 `CREATE OR ALTER … AS <体>` |
| 语句生成 | `core::routine::plan_save` | 在 `CREATE` 关键字**之后**插包装词（注释原样保留）；已带 `OR REPLACE` / `OR ALTER` 不重复包装；MySQL 的 `ALGORITHM=/DEFINER=` 前缀不受影响；PG 触发器的 `DROP TRIGGER … ON <表>` 从源码解析表名，解析不出就报错而不是拼错 SQL |
| 源码读取 | `Core::request_routine_source` → `MetaEvent::RoutineSourceLoaded / RoutineSourceFailed` | 复用 `MetadataProvider::object_ddl`；MSSQL 侧新增 `sql::routine_source_sql`（`OBJECT_DEFINITION(OBJECT_ID(…))`），其余五方言原本就能取视图 / 例程定义 |
| 保存下发 | `Core::apply_routine_save` → `Core::apply_statements` | 与迁移共用同一条 DDL 通道，因此同样受**只读连接拦截**与**生产连接写解锁**约束；失败保留草稿 |
| 源码面板 | `ui/src/main_view.rs::render_routine_panel` | 标题（对象 · 种类）+ 搜索框（`/ 处匹配` + 上一处 / 下一处）+ 编辑器 + 底栏（失败明细 / 降级原因 / 脏提示）+ 「还原」「保存」 |
| 搜索 | `InputBaseState::set_search_query` / `next_search_match` / `previous_search_match` | 复用 gpui 编辑器自带的查找会话，不自己实现匹配 |
| 脏草稿保护 | `routine_dirty` / `routine_discard` | 草稿与原文不同即为脏：关闭面板先弹「放弃未保存的修改？」；`Esc` 先关浮层再关面板（脏时仍走确认） |
| 显式降级 | `RoutineSupport::reason` | 驱动不支持保存时编辑器转只读，底栏写明原因（如「SQL Server 只返回函数体，无法还原函数签名，不能安全保存」），不是默默禁用按钮 |
| 入口可见性 | `object_menu_groups` | 对象右键「查看 / 编辑源码」只对例程出现，且要求驱动开了 `routine_source_edit` 能力位（R5：不假装支持） |

**测试**：`core` 侧 14 例（各方言策略矩阵、`CREATE OR REPLACE` 插入位置、已有包装词不重复、MySQL `DEFINER` 前缀、
DROP+CREATE 的警告与两条语句、PG 触发器带所属表、解析不出时报错、MSSQL 体 → 完整语句、空源码与非 `CREATE` 源码被拒、
前置注释不挡住 `CREATE` 关键字）；UI 侧 3 例（源码入口按能力位与对象种类出现、例程种类映射、面板渲染 + 脏草稿关闭确认）。
`cargo test -p rustdb-core --lib` → **147 passed**；`cargo test -p rustdb-ui --lib` → **96 passed**；
`cargo check --workspace --all-targets` 通过（仅既有 `MetadataProvider` 未用警告）。

**边界**：MSSQL 的函数 / 触发器与各方言的物化视图**只能看不能存**（拿不到签名 / 所属表，保存会拼出错的 SQL）；

`cargo check --workspace --all-targets` 通过（仅既有 `MetadataProvider` 未用警告）。

**修掉的真问题**（都是这轮实测出来的，不是推测）：

1. **遮罩吃掉卡片内的点击**：GPUI 的遮罩与卡片是兄弟节点，遮罩的 `on_click` 对卡片内的点击同样触发，
   于是「保存」校验失败时浮层先被关掉、错误提示跟着一起消失。修法：卡片加 `.occlude()`（GPUI 官方的
   `HitboxBehavior::BlockMouse`），卡片里的点击不再落到遮罩上。**只读连接 / 生产标记等既有浮层不受影响**。
2. **浮层高度塌成 80px**：卡片只有 `max_h`、高度随内容自适应，正文却写了 `flex_1` + `min_h_0`
   （父高度不定 → flex 基准为 0 → 正文高度为 0）。结果是**字段全都溢出到卡片外、看不见也点不到**。
   修法：正文改成 `max_h(470px)` + 自滚动，卡片高度随内容自适应。

**边界**：**口令和私钥口令只留在内存**（`dev_secret` / `dev_passphrase` 都是 `#[serde(skip)]`，绝不落盘）——
系统密钥库后端还没接，重启后需要重录，UI 里写明「口令（只留在内存）」；
`known_hosts` 用 OpenSSH 格式（`host key` 与 `[host]:port key` 两种写法都认，哈希记录也能被替换掉）；
隧道走本地转发，驱动看到的是 `127.0.0.1`，**按主机名做 TLS 校验的场景（如 PG `sslmode=verify-full`）会失败**；
`InsecureAcceptAny` 只在契约层存在，UI 不给开关；Oracle 等需要客户端安装的驱动在隧道下不做额外处理。

### 9.26 F-96 CLI 与脚本集成

F-96 的前提是「CLI 与 GUI 共用 core 服务，CLI 不直接持有驱动」（需求 19.5）。为此先把驱动注册从 `app` 抽成

| 项 | 位置 | 说明 |
|---|---|---|
| 组合根 | `bootstrap/src/lib.rs`（新 crate `rustdb-bootstrap`） | `driver_registry()`（六方言工厂）+ `open_profiles()` + `open_history()` + `build_core()` / `build_core_with(profiles, history)`。**`app` 与 `cli` 都只依赖它**，两边都不再直接引用驱动 crate |

| 全局选项 | `--json` / `--connections <路径>` | `--json` 输出机器可读信封；`--connections` 换连接配置文件（脚本用独立配置，不碰用户配置） |
| 错误码 | `cli/src/error.rs` | `E_USAGE`=2、`E_CONFIG`=3、`E_CONNECT`=4、`E_PERMISSION`=5、`E_QUERY`=6、`E_TIMEOUT`=7、`E_IO`=8、`E_INTERNAL`=1。错误写 **stderr**（`--json` 时是 `{"error":{"code","message"}}`），退出码非零且**稳定可脚本判断** |
| 默认只读 | `cli/src/gate.rs::check` | 语句经 `core::review` 逐条定级；只读语句直接放行，任何写语句**必须显式 `--write`** |
| 危险 SQL 二次开关 | `cli/src/gate.rs::analyze` | `DELETE` / `DROP` / `TRUNCATE` / 无 `WHERE` 的 `UPDATE`·`DELETE` 需再加 `--danger`；多语句逐条判定（整段送审会把批次一刀切） |
| 生产拦截 | `cli/src/gate.rs::check` | 连接标了「生产」时**即使带 `--write --danger` 也拒绝**（CLI 没有解锁窗口）；只读连接同样一律拒绝写入 |
| 门控时机 | `cli/src/commands/query.rs::run` | 门控在**连库之前**：缺开关的请求根本不碰数据库 |
| 执行链路 | `cli/src/runtime.rs` | 订阅事件总线 → `core.connect` → 等 `ConnEvent::Ready` → `core.execute_with_source(..., HistorySource::Cli)` → 等 `QueryEvent::Completed`；历史来源标记为「CLI」 |
| 主机密钥 | `cli/src/runtime.rs::connect` | 遇 `ConnEvent::TunnelHostKey` 直接报 `E_CONNECT`「请在桌面端确认后重试」——**CLI 不代替用户接受密钥** |
| 输出格式 | `--format table/csv/tsv/markdown/json` | 表格 / CSV / TSV / Markdown 复用 `core::export::write_rows`（单元格编码、NULL、公式防护**只有一处**）；JSON 是信封（`elapsed_ms` / `warnings` / `notices` / `results[]`） |
| 上下文导出 | `cli/src/commands/context.rs` | Markdown 或 JSON：对象清单 + 列 / 主键 / 可空 / 默认值；**不含主机、账号、口令、密钥引用**（19.5） |
| 结构文档 | `cli/src/commands/dump.rs` | SQL / Markdown / JSON；取不到 DDL 的对象**显式列出原因**，不静默丢弃 |
| SQL 来源 | 位置参数 / `--file` / 标准输入 | 标准输入非终端时才读；交互终端下不读，直接报用法错误 |
| 口令 | `RUSTDB_PASSWORD_<ID>` / `RUSTDB_PASSWORD` 环境变量 | 只注进内存（`Core::set_profile_secret`），**不落盘** |

**测试**：`cli` 单元 20 例（参数解析、错误码与退出码契约、写入门控判定）；
`cli` 集成 19 例（直接跑 `CARGO_BIN_EXE_rustdb-cli`：默认拒写、写开关放行、危险语句要二次开关、
只读 / 生产连接带开关仍拒、连接失败 4、配置缺失 3、SQL 错误 6、JSON 信封、CSV 输出、上下文不含凭据）。
`cargo test --workspace` → **429 passed**（0 failed）；
`cargo check --workspace --all-targets` 通过（**0 warning**，顺手清掉 mssql / oracle live 用例里两处未用导入）。

**修掉的真问题**（实测出来的，不是推测）：

1. **元数据加载失败被静默吞掉**：`schema` 原来直接读 `core.objects()`，驱动报错时目录里就**空空如也**，
   看不出是「空库」还是「加载失败」。修法：`runtime.load_objects` 改为等 core 的
   `MetaEvent::Loaded / LoadFailed`，失败按 `E_QUERY` 报出来。
2. **`--write` 被当成未知选项**：参数解析把 `--` 前缀剥掉后没匹配到分支，报「query 不支持选项 write」。

**边界**：CLI 不做交互式主机密钥确认（需在桌面端确认后重试）；不支持 `--file` 与位置参数同时给；
`dump` 只导出 DDL，不导数据；`context` 默认最多 50 个对象（`--max-objects` 可调）；
生产连接**没有**解锁窗口，这是与桌面端的刻意差异。


### 9.27 F-92 AI SQL 优化与方言转换

需求原文：解释、优化、改写与跨方言转换；输出 diff 供逐段采纳/拒绝；不自动执行；可选目标方言并说明不兼容点；
结果可一键插入编辑器或新标签。实现沿用 F-51/F-98 的边界：**模型只产文本，执行仍走原入口**。

| 项 | 位置 | 说明 |
|---|---|---|
| 任务种类 | `core/src/optimize.rs::OptimizeKind` | 解释 / 优化 / 改写 / 转换；改写要补充要求，转换要目标方言，解释允许只给文字 |
| 请求 / 结果 | `OptimizeRequest` / `OptimizeResult` | 请求带源方言、目标方言、要求、结构摘要；结果带说明、模型要点、**本地判定的方言提示**与 diff |
| 回答解析 | `parse_answer` | 取第一个 ```sql 代码块；块外 `-` / `*` / `•` / `·` 开头的行作为改动/风险点，其余作为说明；解释模式没有代码块也合法 |
| 逐段采纳 | `diff_hunks` / `apply_hunks` | 行级 LCS，切成连续改动段（前后各带 2 行展示上下文）；`apply_hunks` 从后往前拼接，被拒绝的段保持原文；超过 800 行退化为整段替换，避免大 SQL 卡界面 |
| 方言要点 | `dialect_rules` | 六方言各一段（引用符、分页、自增、日期、拼接、特殊能力），进系统提示 |
| 不兼容点 | `check_incompatible` | **本地词法检查**，不靠模型自检：MSSQL 的 `LIMIT`、PG 的反引号、MySQL 的 `RETURNING`、Oracle 的布尔字面量等；字符串与注释里的同名词不会误报 |
| 一次调用 | `Optimizer::run` | 不挂工具（`tools: []`）、不碰 session；模型若返回工具调用直接报错；需要 SQL 的任务缺代码块时报「重试」而不是拿说明当 SQL |
| Provider 复用 | `AgentEngine::provider()` / `AgentEngine::schema_digest()` | 优化面板与 Agent 共用同一个 `LlmProvider`；结构摘要抽成关联函数，两处口径一致 |
| 请求体 | `OpenAiProvider::request_body` | 工具为空时**不再发空 `functions`**（部分兼容端点会据此强制调函数）；`next()` 复用同一构造，去掉重复代码 |
| 工具栏入口 | `ui/src/main_view.rs`「优化」按钮（`ai-optimize`） | 取编辑器选区或全文作为原文；没有查询页/空 SQL 时给状态栏提示 |
| 面板 | `OptimizePanel` + `render_optimize_panel` | 种类胶囊、目标方言（仅转换）、改写要求（仅改写）、生成/重新生成；说明 + 方言提示 + 模型要点 + 每段 diff 的「采纳/跳过」 |

**本轮修复**

1. `Core::fetch_page` 在调用方线程没有 Tokio reactor 时 panic（SQLite 打开表直接崩溃）。改为在
   `self.runtime.spawn` 内执行会话分页；新增回归测试 `fetch_page_survives_without_caller_runtime`
   （手写无 reactor 的 `block_on`，不依赖调用方运行时）。
2. `db-sqlite` 的 `table()` 谎报 `engine = "SQLite"`，让设计器把元数据当成用户改动，未动的表也提示
   「SQLite 没有表级存储引擎设置」。改为 `engine: None`，未改动表的预览回到「没有改动」。
3. 离线演示模型的首个回合固定是工具调用，优化器只接受文本 → 面板报内部错误。UI 在生成前识别
   `offline-demo` 并给出可操作提示；core 侧错误文案也改为「请换用支持文本回答的模型」。
4. 文案收敛：设计器页脚「先预览，再执行」、血缘页脚「点行打开对象」、单元格详情「只读」、
   短值详情面板按内容收缩（≤64B 140 / ≤160B 200）、SQL 预览浮层按行数自适应（180–420）。
5. 布局用例可重复：`cards_fill_the_window` / `switching_panels_uses_that_panels_own_width` 原先
   从本机真实 `layout.json` 启动，拖拽过的宽度会让断言随环境漂移（实测侧栏卡片 244.5 而非 251）。
   测试改为用临时布局文件构造 `MainView`，不再读写用户配置。
