## 3. 本轮修复的缺陷

### 3.0 右键菜单「能弹但点了没反应」

- **现象**：菜单正常弹出，点任意项只是菜单关闭，动作从未执行。
- **根因**：遮罩 `*-scrim` 用 `on_mouse_down(Left)` 关闭菜单，而菜单项是 `anchored()` 的 deferred 子元素。
  mouse_down 阶段遮罩先命中最上层并关闭菜单，菜单项随即消失，收不到 mouse_up → `on_click` 永不触发。
- **修复**：所有菜单遮罩改用 `on_click` 关闭（与库下拉框一致）。
- **验收**：`menu_click_dispatches_actions`（UI）、`menu_actions_execute_against_sqlite`（core），
  实机截图 `docs/images/nav-fix-ddl.png`、`docs/images/nav-fix-open.png`。

### 3.1 取消静默失效（M-07 不达标）

- **现象**：`cancel()` 返回成功，但查询继续跑完，UI 一直等到 `Completed`。
- **根因**：驱动在 `execute` 里**自己**生成 `QueryId`（`QueryId::new()`）并记为 active，
  而 `Core::cancel` 传的是 core 侧分配的 id —— 两者永不相等，`active.as_ref() == Some(query_id)`
  恒为 false，中断从未下发。
- **修复**：`ExecuteRequest` 新增 `query_id: Option<QueryId>`，core 下发自己的 id，
  驱动优先用它作为 `QueryHandle::query_id`（sqlite / postgres / mysql 三处）。
  契约变更已同步到需求文档 7.4 节。
- **验收**：`core/tests/perf.rs::m07_cancel_interrupts_long_query`。

### 3.2 告警被误判为「结果截断」

- **现象**：任何产生 warning 的语句都被标记 `truncated`，底栏显示「仅显示前 300 行」。
- **修复**：`truncated` 改为「加载行数达到 `max_rows`」判定；告警改走独立 `Notice` 事件。

### 3.3 列宽不铺满容器

- **现象**：两列结果只占结果区一半宽度。
- **修复**：`ResultView.widths` 改为 `Vec<Option<f32>>`；未拖过的列用 `flex_1` 均分，
  拖过的列定宽（`flex_shrink_0`）。横向滚动上限改由 `min_total_width()` 计算。
